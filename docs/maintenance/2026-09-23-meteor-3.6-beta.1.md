## Additional implementation evidence

The audit's E01-E07 evidence remains authoritative for shipped Meteor behavior.
Verification exposed details that warranted narrower guidance:

- Beta.1's TypeScript scaffold installs npm TypeScript 7 and a separate
  `TsCheckerRspackPlugin` checker. Copying the guide's older `baseUrl` option
  into that scaffold fails with TS5102. Native examples now use relative
  `paths` targets and preserve the installed compiler, resolver and checker.
  [TypeScript 7's release documentation](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)
  confirms the removed `baseUrl` and `node` resolution options.
- Adding only a native barrel under `files` can disable previously implicit
  application-source inclusion. Preserve the source set explicitly and verify
  it with `--listFiles` and a deliberate failing assignment. A zero-error
  compiler run that never reads application files is not acceptance evidence.
- `accounts-base/accounts_server.js` supplies the default rule's name and
  connection matchers. `rate-limit/rate-limit.js` includes both actual values
  in its counter key. Accounts methods share a rule, not one combined counter;
  the rule resets counters on its interval rather than aging out each request.
- `accounts-base/server_http_cookies.js` gives set/clear credentialed CORS;
  refresh rejects `same-site` and `cross-site` Fetch Metadata and does not gain
  CORS through the allowlist. A successful cross-origin set is not evidence
  that refresh is supported there.
- Instrumentation's new documentation is absent from the current `devel`
  paths. Its reference links the exact beta.1 documentation revision while
  retaining the existing valid logging Source footer.

## Remaining review and possible scope

The repository contract requires an outside contributor to run affected
high-risk/routing cases in Claude Code or Cursor before a PR. That independent
review is pending; these agent-run conversations do not satisfy it. No PR,
push, tag or publication was performed.

After the audit, the user asked whether TypeScript merits its own skill. A
focused `meteor-typescript` would own app declaration providers, configuration,
editor resolution and type-checking across upgrades and ordinary development.
Migration would retain its upgrade checkpoint and hand off; modern build would
retain transpilation/checker integration. Generic TypeScript teaching and
Atmosphere package publishing would remain outside that scope. Creation was
recommended but not authorized at the time of this review, so this change
keeps the confirmed migration guidance in its existing owner.
