## Source discrepancies and limits

- The changelog and some prose say `@meteorjs/rspack@3.0.0`, but the tagged
  constants and manifest select `3.0.0-beta.1`. Use the exact beta pairing.
- The Rspack guide says manual npm instructions include `--legacy-peer-deps`
  during the old-peer transition. At the tag, `ensurePackageDependencies`
  passes the flag to automatic installs and returned command metadata, but
  `renderManualInstallInstructions` recomputes displayed commands without it.
  Document a conditional one-invocation fallback for confirmed Rspack 1.x
  peers; do not promise the warning includes it or disable peer checks globally.
- Upstream Rspack 2 stops reading `.swcrc` itself. Meteor still reads the app's
  SWC file in `lib/swc.js` and supplies the resulting loader options. Preserve
  valid Meteor configuration instead of applying the generic removal blindly.
- No browser, native device, package-install or model acceptance result is
  inferred from reading upstream tests. Fresh outcomes belong in the release
  review record, separate from this pre-edit report.

## No-action findings

- Generic `meteor create` Git URL inference and source/ref/subdirectory flags
  are documented CLI conveniences. Existing app scaffolding is sufficient;
  no new general-purpose CLI skill is proposed. Git package adoption has a
  distinct local-override/reproducibility decision covered by F08.
- Parallel npm installation and bounded prefetch are automatic optimizations.
  Do not expose contributor-only concurrency knobs or claim warm-cache gains
  without measurement. Preserve first-build versus repeated-build evidence.
- React 19.2 skeleton dependencies do not require upgrading an existing React
  17/18 app solely for the compiler; use its supported target/runtime branch.
- New HMR guards do not add Blaze hot template replacement, native HMR, offline
  collection synchronization, or a need to rebuild binaries for every web edit.
